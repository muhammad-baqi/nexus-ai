# Website Bookmarks

## Overview

Website Bookmarks let a user save a URL and have Nexus automatically
fetch useful metadata (title, description, preview image, favicon)
rather than requiring the user to type all of that in by hand. This is
the primary "passive capture" feature of the MVP — the browser extension
(a future phase) will build on the same underlying metadata-fetch
mechanism.

## Requirements

Users shall be able to:

- Paste a URL to create a new bookmark
- Have Nexus automatically fetch: page title, meta description, Open
  Graph image, favicon, canonical URL, and domain
- Edit the fetched title/description if desired
- View the bookmark with its preview image and domain
- Optionally view a full-page screenshot (best-effort)
- Retry metadata fetch if it failed
- Tag, favorite, archive, move, trash, and share a bookmark (shared
  behavior)

## Save Flow

```
User pastes URL
      │
      ▼
Immediate save (URL only, status: "fetching metadata…")
      │
      ▼
Background job fetches metadata
      │
      ├─ Success → item updated with title, description, image, favicon
      │
      └─ Failure → item kept with URL as title, status: "metadata
                    unavailable," manual retry available
```

The key requirement here is that saving is **never blocked** on the
metadata fetch. The item is created and visible to the user immediately
with just the URL; metadata fills in asynchronously. This keeps capture
fast (per the Vision's "seconds, not longer" principle) even if the
target site is slow or unreachable.

## Metadata Extraction

On save, a background job fetches the target URL server-side and
extracts, in order of preference:
1. Open Graph tags (`og:title`, `og:description`, `og:image`)
2. Standard HTML `<title>` and `<meta name="description">`
3. `<link rel="icon">` for favicon (falling back to `/favicon.ico`)
4. The canonical URL (`<link rel="canonical">`), falling back to the
   submitted URL if absent

**Normalization:** store both the exact URL the user submitted and the
canonical URL/domain separately, since they may differ (tracking
parameters, redirects).

## Screenshot (Optional)

- A full-page or above-the-fold screenshot may be captured as a
  best-effort enhancement, generated by the same background job or a
  follow-up job.
- Screenshot failure must never block or fail the bookmark save itself —
  it's a nice-to-have overlay on top of the core metadata.

## Reading Mode (Optional Enhancement)

- A simplified, readable extraction of the article's main text content
  may be offered as a "reading view" for supported pages.
- Not required for MVP completion but may be included if time allows
  within Friday's scope; if included, it should degrade gracefully
  (simply unavailable) for pages where extraction isn't feasible (e.g.,
  heavy JS apps, paywalled content).

## Duplicate Detection

When a user pastes a URL that (after canonicalization) matches an
existing, non-trashed bookmark in the same account, show a prompt:
"You already saved this — view existing bookmark?" rather than silently
creating a duplicate. The user may still choose to save a duplicate
intentionally (e.g., wanting it in a different Collection).

## Background Job Requirements

- Metadata fetching must run as an asynchronous background job (not
  inline in the request/response cycle), with a reasonable timeout
  (e.g., 10 seconds) after which the job marks the item as
  "metadata unavailable" rather than hanging indefinitely.
- Jobs must handle: unreachable hosts, non-HTML responses, malformed
  HTML, and redirects (following a reasonable number of hops before
  giving up).
- Retries: the user-triggered "retry metadata fetch" action re-enqueues
  the same job; there is no automatic silent retry loop that could hammer
  the target site.

## Search Integration

Title, description, and domain are indexed for Global Search. The raw
page content is **not** fetched/stored/indexed in the MVP (that's a
larger "reading mode" / archival feature, not required here) — only the
metadata described above.

## Error States

- Invalid URL format: inline validation before submission.
- Unreachable/non-existent URL: item still saves (with the URL as
  title), metadata status shows "unavailable," manual retry offered.
- Site blocks automated fetching (e.g., returns 403 to the fetch job):
  same "unavailable" handling — this should not be surfaced as an
  application error, since it's expected behavior for some sites.
- Duplicate URL: non-blocking prompt as described above, not a hard
  rejection.

## Out of Scope for MVP

- Full-page archival/permanent snapshotting (storing a complete offline
  copy of the page)
- Rich embeds for specific platforms (YouTube players, tweet embeds,
  etc.) — see `02_Development/` for future direction on rich social
  media previews
- Browser extension for one-click save from the current tab (future
  phase, see `02_Development/Browser_Extension.md`)

## Acceptance Criteria

- [ ] Pasting a valid URL immediately creates a visible bookmark item,
      with metadata filling in asynchronously.
- [ ] A user can edit the fetched title/description after the fact.
- [ ] Failed metadata fetches leave a usable item (URL-only) with a
      manual retry option, not a broken or missing item.
- [ ] Saving a URL that (after canonicalization) duplicates an existing
      bookmark triggers a non-blocking duplicate prompt.
- [ ] Covered by unit tests (URL canonicalization, metadata parsing),
      integration tests (background job success/failure/timeout paths),
      and an end-to-end test: paste URL → see metadata populate → edit →
      search for it by title.
